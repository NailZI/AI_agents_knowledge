# GLM как внешний исполнитель Codex

Статус на 2026-11-09: отдельная подзадача успешно выполнена через `codex exec --profile glm`; основная конфигурация Codex использует OpenAI. Это локальная настройка пользователя, а не проверенная переносимая установка для других машин.

## Выполненные шаги

1. Изучена статья об OpenCodex и документация проекта. Установлен OpenCodex 2.99.0 через npm. На этой машине исполняемый файл — `%APPDATA%\npm\ocx.cmd`; отдельная установка Bun не потребовалась.
2. Создан провайдер GLM и запущен локальный прокси на `127.0.0.1:10100`. Ключ пользователь внёс в локальной панели. Значение ключа в документации отсутствует.
3. Сначала был выбран обычный OpenAI-совместимый endpoint `https://api.z.ai/api/paas/v4`. Проверка с этим ключом вернула HTTP 429, код 1113, «Insufficient balance or no resource package». Этот результат относится только к указанному endpoint и не доказывает недостаток средств для другого способа доступа.
4. Сравнена локальная настройка работающего ZCode: он использовал Anthropic endpoint `https://api.z.ai/api/anthropic`. Прямой запрос к нему с тем же ключом вернул HTTP 200 и ответ `OK`. Провайдер OpenCodex назван `zai-api`, адаптер — `anthropic`, модель — `glm-5.3`. Имя `zai` не подошло: встроенный пресет OpenCodex направлял запросы на endpoint Coding Plan.
5. Прокси OpenCodex сначала не мог проверить цепочку TLS-сертификата (`unable to verify the first certificate`). Публичные доверенные корни Windows экспортированы в `%USERPROFILE%\.opencodex\windows-root-ca.pem`; процесс запущен с `NODE_EXTRA_CA_CERTS`, при включённой проверке TLS. Для повторного запуска создан локальный `Start-GLM-Proxy.ps1` в рабочей папке `Codex rulles`. Сам файл сертификатов содержит публичные сертификаты, но является локальным артефактом машины, а не частью репозитория.
6. Через OpenCodex выполнен запрос к `/v1/responses` с моделью `zai-api/glm-5.3`: статус `completed`, ответ `OK`. Вызов Codex CLI с этим провайдером также завершился успешно.
7. Попытка сделать `glm_proxy` глобальным провайдером Codex привела к несовпадению провайдера у старых чатов; список проектов в приложении временно не отображался. Глобальное переключение отменено. Поздняя проверка через инструмент Codex снова вернула проекты. В базовом `%USERPROFILE%\.codex\config.toml` модель — `gpt-6-astra`, провайдер по умолчанию — OpenAI; там осталось только определение `[model_providers.glm_proxy]` с `base_url = "http://127.0.0.1:10100/v1"`.
8. Создан отдельный профиль `%USERPROFILE%\.codex\glm.config.toml`:

   ```toml
   model_provider = "glm_proxy"
   model = "zai-api/glm-5.3"
   model_reasoning_effort = "low"
   ```

   В этой версии Codex профиль подхватывается флагом `--profile glm`; таблица `[profiles.glm]` в основном файле не сработала. Команда `codex exec --profile glm` вернула `OK` с кодом выхода 0.
9. Проверен реальный сценарий внешнего исполнителя: основной чат поручил GLM вычислить первые 48 простых чисел через `codex exec --profile glm --ephemeral --skip-git-repo-check -s read-only`. GLM вернул список от 2 до 223, процесс завершился с кодом 0; основная задача сверила список независимым расчётом.

## Правило делегирования

В активный `%USERPROFILE%\.codex\AGENTS.md` и исходник `codex/AGENTS.md` добавлен раздел «Подзадачи и исполнители». Для сложной задачи он предписывает выделять независимые части, сначала давать подходящую часть внешнему исполнителю через проверенный профиль CLI, а при недоступности или непрошедшем проверку результате — доступному встроенному субагенту либо выполнять её самостоятельно. Основная задача задаёт границы, не передаёт секреты без необходимости, проверяет каждый результат и отвечает за интеграцию. Простой шаг не требуется делегировать.

## Ограничения и диагностика

- Встроенный `spawn_agent` дважды отказал модели `zai-api/glm-5.3` с `Unknown model`; профиль CLI не добавляет GLM в список встроенных субагентов. Поэтому успешный запуск через CLI называется **внешним исполнителем**.
- Автоматическая интеграция OpenCodex в Codex сообщала об отказе проверки Windows-пути координатора из-за перенаправления в MSIX LocalCache. Использовано штатное определение пользовательского провайдера Codex; защитная проверка OpenCodex не отключалась.
- Прокси должен работать во время GLM-подзадачи. Автозапуск Windows не настроен. Взаимодействие GLM с инструментами и работа профиля в GUI не проверялись.
- Наблюдавшийся HTTP 429 на `/api/paas/v4` не связан доказанным образом с лимитом ChatGPT; не следует приписывать ему эту причину без отдельной проверки.
- На этой машине запуск Codex CLI внутри ограниченной песочницы не смог открыть собственную базу; успешные проверки выполнены вне неё с явным режимом `read-only` для работы агента.
